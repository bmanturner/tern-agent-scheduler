# Local prior art: tern-swarm, tern-rss, omp-pushover, ternkit

Scope: read-only review for a "scheduled agent jobs" Tern plugin. All paths are under `/Users/bfturner/Dev/personal/`. Line numbers are file-relative; docs are cited as `file:line` or `file §section`. Anything unverified is marked `[INFERENCE]`.

Short version: **tern-swarm is the template.** Its window half already does what a scheduler needs: a leader-elected tick loop, `cx.agents:start` with an omp role, intents from host forms, repository approval, Carly exports and a status segment. The scheduler is a much smaller state machine (a job fires, a run is tracked), so a lot of swarm's machinery (worktrees, checks, shipping, board) can be dropped.

## 2. Pitfalls and Tern quirks learned

Each is a thing that has bitten these repos.

1. **Hook time budgets (hard).** Window calls (events, timers, commands, canvas actions, Carly exports) have 50 ms. Chrome formatters and `available` have 4 ms. Host calls (block `init`, `view`, `key`, `event`) have 2 s. A call over budget raises `tern: <hook> exceeded <n> ms`, **`pcall` cannot catch it**, and Tern **disables that hook until reload** (`tern-swarm/AGENTS.md:95-107`; `docs/how-it-works.md §Known limitations`, "Tern can disable Swarm", ~lines 155-165). A loader step over budget disables *every* timer, so `register()` never runs (`AGENTS.md:86-88`).
2. **Module compile cost.** Tern compiles every chunk to native code on `require`, so loading all of swarm's window half at once takes more than 50 ms. Load one module per `tern.timer(0)`, list modules in dependency order, and warn at ≥15 ms (`window.luau:1-8`; `AGENTS.md:79-85`). Do not register a second `focus` handler (`AGENTS.md:86-88`).
3. **Window-half timers run late in the background.** `docs/how-it-works.md §Known limitations` (last bullet) and `docs/troubleshooting.md` (last symptom row): on macOS, delays of **40-90 s** were seen while Tern idles in the background, until a focus event or a `tern` CLI call wakes the window. A gap of ≥1 min looks like a stall to the watchdog. ⇒ A cron scheduler must be tolerant: compute `due = next_run <= now`, catch up on the next tick, and define a missed-run policy (run once, skip, or never run runs older than N).
4. **Orchestrator only exists while a window is open.** "The orchestrator runs inside a Tern window; when every window is closed, nothing moves" (`docs/configuration.md:10-11`). The window half is the only place with `cx.agents`. The host half (daemon) keeps blocks alive across window close, but has no `cx`. ⇒ **A scheduler cannot fire jobs with no Tern window open.** `tern daemon` keeps panes alive but does not run window plugins `[INFERENCE from swarm's and rss's docs]`.
5. **tern-rss's poll loop is host-side and only runs while an RSS block is attached** (`store.luau:1-5` header, `tick` at ~L690-713: stops when `subscribers` is empty; `README.md §Refresh and toasts`). It is the *wrong* model for a scheduler that must fire without a visible block. A host loop also has no `cx` and cannot start agents.
6. **Several windows ⇒ several VMs of the window half.** Without a lease each would start every job. Swarm's lease is in `tern.kv` (`orchestrator.luau:40-56`), with a 10 s TTL, 2-consecutive-tick confirmation and an epoch. Remember to reset all leader caches on gaining *or losing* leadership (`new_epoch`, `orchestrator.luau:60-77`).
7. **`tern.fs` has no rename, stat or locking**; writes aren't atomic. A crash mid-write can leave a broken file (`AGENTS.md:117-118`; `docs/how-it-works.md §Known limitations`, "A damaged state file"). Mitigations used: `.bak`, `.corrupt`, refuse to overwrite a damaged file, only one writer (the leader). The TS side of omp-pushover *can* use tmp+rename (`state.ts:84-94`), but the Luau side just overwrites (`tern-plugin/window.luau:58-70`).
8. **`tern.json` quirks**: empty tables encode as `{}`: wrap lists in `tern.json.array()`; `decode` drops `null` members; use `tern.json.null` to write null; `encode(v, true)` pretty-prints (`AGENTS.md:115-116`; `omp-pushover/tern-plugin/window.luau:62-69`).
9. **Luau syntax**: `m.X: T = …` on a table field is a syntax error (`AGENTS.md:111-112`). Strict mode rejects a computed `require` path, so use `local load_module: (string) -> any = require :: any` (`window.luau:52-54`; `tern-rss/host.luau:73-75`). Never `pcall(require, …)`: a C caller breaks relative resolution, so use a closure (`tern-rss/host.luau:110-111`).
10. **Callbacks get a fresh `cx`**; never stash a `cx` and use it later. Host-half callbacks get no `cx` (`AGENTS.md:119-120`). `tern.process.run` callbacks get `(result, cx)` (`lib/run.luau:129-135`). Where there is none, `state.notify` queues a toast for the next tick (`lib/state.luau:81-84`).
11. **`cx:toast` levels** are only `"success"`, `"info"`, `"error"` (`AGENTS.md:121`).
12. **`tern.process.run` has no shell and a short PATH.** Always spawn an absolute path (`AGENTS.md:122-123`; `lib/bin.luau`; `docs/troubleshooting.md` row 1: "omp was not found in …" → set `bin_dirs`). `ternkit/lib/bin.luau:4-5` has a shorter list (`/opt/homebrew/bin, /usr/local/bin, /usr/bin`) that would *not* find `~/.local/bin/omp`; swarm's version adds `~/.local/bin`. Tern's bundled omp lives at `~/Library/Application Support/Tern/omp/bin/omp` (from the task brief), which neither default list covers. `[INFERENCE]` Use `command = "omp …"` in `cx.agents:start` (resolved by the pane shell) and keep the explicit path for background spawns.
13. **Host block `key` returns exactly `false` only when nothing changed**; `false` skips render and save. Return `nil`/`true` when handled (`AGENTS.md:113-114`; `ternkit/README.md §Add a block`, step 6; swarm blocks `return nil` after handling and `false` for unhandled, `new-task.luau:299-347`).
14. **`view` always returns `{ main = ui.col({…}) }`**: a region's root node is never drawn (`ternkit/README.md`, step 6). Give list items and child nodes stable `key`s (`new-task.luau:156-161`; `panel_cards.luau:10-35`).
15. **Cursor in `input`/`editor` is UTF-16 code units** while Luau strings are bytes; convert (`tern-rss/blocks/rss.luau:509-535`; `lib/textfield.luau`). Block focus is moved with `cx:frame({{"focus","main.<key>"}})`, and `cx:render()` must run first when the node is new (`rss.luau:286-298`).
16. **Never write into the package folder**: any change there reloads all plugins and loops (`AGENTS.md:130-132`). A *linked* package reloads the user's live Tern on every save (`AGENTS.md:181-185`). Say so before linking.
17. **Logging**: the default filter drops `print`, `tern.log.info` and `debug`. Use `tern.log.warn` with a `plugin:` prefix. Window half → `~/Library/Logs/Tern/tern.log`; host half → `tern-daemon.log`. To see info logs, restart Tern with `STENCIL_LOG=warn,stencil=info,tern::plugin=debug`; the daemon keeps its old env until it restarts (`docs/troubleshooting.md §Logs`; `AGENTS.md:164-167`). Window-half load errors show only as a toast and in `tern.log`, never in `tern plugin list` (`AGENTS.md:179`).
18. **Carly `sig`/`doc` limit 1024 bytes** or registration aborts (`carly.luau:25-42`). Wrap `register()` in `pcall` so a Carly failure doesn't stop the orchestrator (`window.luau:93-101`). Gate on `if tern.carly`.
19. **Feature-gate the window API**: `cx.board`, `cx.agents`, `cx.canvas`, `cx.layout` may be nil on an older Tern. Swarm checks once and turns itself off with a warn (`orchestrator.luau:200-207`). Swarm was developed against Tern **0.5.2** (`docs/configuration.md:10`; `README.md:9`) and tern-rss against **0.6.1** (`README.md §Requirements`). The installed Tern is 0.7.2, so re-verify `cx.agents` semantics. Note `tern.d.luau` in each repo is generated (`tern plugin types .`) and may be older (`AGENTS.md:18`).
20. **iOS**: swarm returns at once on `tern.runtime.os == "ios"` (no `tern.process`). Remote/SSH panes are refused: `cx.hosts:current().kind == "remote"` (`window.luau:10-12`; `commands.luau:13-26`).
21. **Pane liveness**: blocks have no close hook; poll `tern.pane.list()` (host) or `cx.session:pane(id)` (window). Restarting a block reuses its pane id, so a new poller must replace the old one (`ternkit/lib/poll.luau:240-262`).
22. **Agent-prompt delivery can fail silently** → `a.delivery_error` and the 180 s `PROMPT_STALL_S` guard, which blocks the task (`steps.luau:165-182`; `const.luau:17`). An agent that exits shows `a.state == "exited"` (time limit or crash) vs. pane closed (`a == nil`) (`steps.luau:101-113`). The final `last_message` can arrive *after* the `idle` report (`steps.luau:125-130`), so wait for it before recording a summary.
23. **Idle-after-run signal needs `busy_seen`**: an agent can report `idle` before it ever worked, so compare a message key with a baseline (`steps.luau:165-182`). A scheduler must not treat the initial idle as "finished".
24. **`cx.layout:move` can fail**; retry twice then fall back to separate tabs (`steps.luau:197-216`). `layout:focus` restore uses `cx.session:focused()` before and after (`prepare.luau:32,66-70`).
25. **Changing settings**: after writing a settings file call `config.forget()`, write a `{kind="config"}` intent and open `swarm://wake`; otherwise the leader's 30 s config cache (`const.CONFIG_CACHE_S`) delays the change (`AGENTS.md:156-159`).
26. **Intent queue is not a security boundary**: any program running as the user, including an agent, can write an intent and e.g. approve its own task (`README.md §Security and trust`). The same would be true of a scheduler's job file: an agent could schedule itself. Decide whether that's acceptable.
27. **Shell `--approval-mode`**: swarm's default `agent_args = {"--approval-mode","yolo"}` because nobody watches; a user value *replaces* the default; approval/config flags can only come from the user layer (`docs/configuration.md:270-278`, `schema.luau:225-262`). Plugin argv tokens are restricted to `^[%w%-_=.:/@]+$` (no spaces, `~`, `,`, `*`), which is why `--config` paths cannot contain spaces (`docs/configuration.md §Agent skills`). That matters because Tern's data folder is `~/Library/Application Support/…`, a path with a space.
28. **omp nesting**: omp-pushover's extension returns early when `process.env.OMPCODE === "1"` so subagent omp processes don't double-report (`src/index.ts:19`). An omp-side extension for scheduling needs the same guard. It also distinguishes main vs sub agents with `ctx.agent.kind === "main"` or `ctx.hasUI` (`index.ts:28`).
29. **Extensions load only at omp start**: already-running sessions never run a newly-installed extension (`omp-pushover/README.md §Troubleshooting`). Another reason to prefer a plugin-only design.
30. **Don't depend on shell state for jobs**: swarm types a generated `sh` script into a pane after checking `info.at_prompt == true and info.busy ~= true` (wait up to 15 s if prompt state is unknown, 120 s if busy, then block) (`lib/jobs.luau:21-40`). Relevant only if scheduled runs must be typed into an existing shell instead of started as agent panes.
31. **Toasts on process/fetch callbacks without `cx`**: queue them and flush on the next tick (`state.notify`, `lib/state.luau:81-84`).
32. **CHANGELOG items about reloads/timers/budgets** (`tern-swarm/CHANGELOG.md`): Watchdog (≈line 59-61: reload only after 30 s idle, ≤1/10 min, 15 min after a focus-first stall); Time budgets (≈line 78-83: modules one per timer callback, leader loads one project per tick, reconcile slices 10 ms/60 ms, intent drain 15 ms, panel redraw split); Damaged state (≈line 67-71); Agent arguments (≈line 32-35: approval flags only from user); Repositories (≈line 72-75: remote panes refused, iOS no-op).
33. **Large-count limits**: board reads are capped at 500 cards per lane (`docs/how-it-works.md §Known limitations`). Not relevant to jobs, but a reminder to cap job and run history lists, and to cap file reads (`MAX_JSON = 262144`, `store.luau:106`).
34. **tern-rss block save** returns only non-secret JSON values; secrets go to the macOS Keychain via `/usr/bin/security` (`ternkit/lib/keychain.luau`, README §Config). Job prompts may contain sensitive text. Store them in `tern.plugin.data`, never in `save`/kv config unless acceptable.

## 3. Per-repo notes

### 3.1 tern-swarm

**Manifest / entry points.** `plugin.toml:1-20`: `id=swarm`, `host="host.luau"`, `window="window.luau"`, two blocks (`new-task`, `settings`, both `palette=false`). `host.luau` only defines these two blocks (6 lines). `window.luau` (142 lines) does everything else.

**How an omp agent is launched.** `prepare.luau:41-46`:

```lua
local command = "omp --model " .. sh.quote("@" .. task.role) .. " --max-time " .. max_time
if #args > 0 then command ..= " " .. table.concat(args, " ") end
local ok, pane = pcall(function()
  return cx.agents:start({ prompt = prompt, cwd = task.worktree, how = "tab", command = command })
end)
```

So: `cx.agents:start` (not `tern new`, not a pane write). `how = "tab"`. `command` carries the omp flags. The prompt is passed separately as `prompt`. The pane number is stored in `task.agent_pane`. Args = user's `agent_args` (default `--approval-mode yolo`), or, when a role config has `agent_args`, the approval args first and then the role's args (`prepare.luau:35-40`). `--max-time` comes from `roles[role].max_time` or `cfg.max_time`. Swarm never uses `cx:run` to start omp; `cx:run(pane, text)` is used to type shell jobs (`jobs.luau:90`) and to send Ctrl-C (`"\3"`, `steps.luau:151`, `actions.luau:193`).

**Roles → flags.** The card tag `#role-<name>` (`const.luau:91`) → `task.role` (`reconcile.luau:386-387`) → `--model '@<role>'`. `default_role` (schema `schema.luau:503`, pattern `^[%w_%-]+$`) is the fallback. The role list is `omp config get modelRoles --json` (`roles.luau:16`). An unknown role blocks the task with a message listing known roles (`reconcile.luau:388-394`). Per-role overrides: project key `roles = { slow = { max_time, agent_args } }`.

**Placement.** The agent starts in its own tab (`how="tab"`), the task's shell is created beforehand (`actions.ensure_shell`), then `cx.layout:move(agent, shell, "up", {focus=false})` stacks the agent above the shell and `layout:resize(shell,"down",8)` shrinks the shell once (`steps.luau:188-216`). The tab is named with a short label + status glyph and coloured per status (`const.luau:59-78`, `steps.luau:217-241`). Focus is restored to the previously focused pane after start (`prepare.luau:32,66-70`). The panel (`cx.canvas:open`) has a user setting `layout.panel = beside | below | tab | none` (`docs/configuration.md:349`; `projects.luau:149-171`) — a ready-made precedent for a "where does the block appear" setting.

**Idle/finish detection.** From `cx.agents:list()` (`taskctx.luau:56-64`) keyed by pane. See `steps.luau:83-184`. `working` ⇒ `busy_seen=true`. `waiting_input` ⇒ status `waiting` + toast. `idle` and `(busy_seen or message differs from baseline)` ⇒ "checking" (finished). `exited` ⇒ blocked with "time limit or crash". `a == nil` with a live pane = still starting, 180 s stall ⇒ blocked. Also `a.delivery_error`, `a.model`, `a.last_message`.

**Polling loop: window half, 3 s.** `orchestrator.luau:310-331` (`tern.timer(const.TICK_MS)` rescheduled after each tick), first tick at 1500 ms (`:367`). Not a `setInterval`. A `command_finished` event on a task's shell pane pokes an immediate tick (`:339-351`, `window.luau:74-77`). A `focus` event also feeds the watchdog.

**Avoiding duplicate work across windows.** Leader lease in `tern.kv["leader"]` (`orchestrator.luau:40-56`), TTL 10 s, 2-tick confirmation, epoch fencing (`state.luau:50-63`). Non-leaders: `publish.refresh_reader()` just re-reads `snapshot.json` (`orchestrator.luau:218-221`).

**Intents queue — design and why.** `store.write_intent` writes `<data>/intents/<unixsec><3-digit counter>-<9-digit random>.json` (`store.luau:247-253`); `pending_intents` sorts and reads (`:255-285`). Kinds: `open`, `create`, `action`, `clean`, `config`, `trust` (`intents.luau:478-531`). Why (from `AGENTS.md:124-126`, `docs/how-it-works.md:54-95` and the code): (1) only the leader writes task files, so no two windows race on `task.json` (and `tern.fs` has no atomic rename or locking); (2) host blocks run in the session daemon with no `cx`, no `cx.agents`, and a 2 s budget; they can only write files and open a URL; (3) any window can be clicked, but only the leader may mutate. Hand-off is `cx:open("swarm://wake")` → `tern.route.link` → `poke()` (`new-task.luau:112`, `window.luau:83-89`). Intents that can't complete yet (task has an in-flight op) return `true` and are retried next tick (`intents.luau:448-449`).

**State & settings files** (`docs/how-it-works.md:97-114`; macOS `~/Library/Application Support/Tern/plugin-data/swarm`): `settings.json` (user), `projects.json` (+`.bak`; `{format=1, projects}`), `snapshot.json` (what panels show), `kv.json` (leader lease, `paused`, `paused_projects`, `watchdog_at`, `trust`), `intents/`, `projects/<id>/{board.md,tasks/<slug>/{task.json,details.md,prompt.md,jobs/<n>-<kind>/…},archive/}`. `tern.plugin.data` is the root (`paths.luau:8-10`). Per-repo: `<repo>/.tern/swarm.json`. Linux: `~/.local/state/tern/plugin-data/swarm`; `TERN_CONFIG_DIR` overrides (`how-it-works.md §Platform support`). `task.json` holds the full record incl. `agent_pane`, `shell_pane`, `role`, `status`, `reason`, `attempt`, `format`, `updated`.

**Settings layering.** User (`settings.json`) vs project (`.tern/swarm.json`). Each key has a scope (`user`, `project`, `both`) and a merge rule (`override`, `user_wins`, additive for `instructions`, narrowing for `carly.actions`, "more private wins" for `tabs.names`) (`docs/configuration.md:209-231`; `schema.luau`). Problems are joined with `; ` and shown in the panel; the default is used for invalid values (`config.luau:258,301-309`).

**Repository approval UX.** The panel header shows a card listing every item the repo makes swarm run, with **Approve** and **Open swarm.json** buttons (`docs/configuration.md §Repository approval`). Approving writes a `trust` intent (`panel.luau:271-277`) and the leader records `kv.trust[root] = subject` (`config.luau:453-467`; `intents.luau:515-530`). A user-originated edit in the Settings page keeps an approved repo approved (`persist` in `blocks/settings.luau:175-215`). While held (`taskctx.luau:22-37`), nothing starts and nothing ships.

**Carly exports.** `open_board`, `add_task`, `list_tasks`, `task_action` + `tern.carly.context` (see pattern 16). Registered inside `pcall` at `window.luau:93-101`.

**Panel block UI.** (a) New-task form: `blocks/new-task.luau` (title `input`, details `editor`, role `list` of `item`s with `detail = model`, `dock` with two lane badges + Cancel + hint line; keys `Tab`, `⌃↵`, `⌃⇧↵`, `Esc`, `j/k` in the list; `save` keeps the draft). (b) The settings page is a single `prefs` node built by `lib/settings_ui.luau` rows and `blocks/settings.luau:916-1100` (pages, sections, rows with `op`, `control`, `changed`, `defaultLabel`, `warning`, `disabled`). (c) Panel canvas: cards (`ui.card`, `ui.kv`, `ui.md`, `ui.row` of `ui.badge` buttons with `actions.click = "act|pid|slug"`), sections "Needs you / Review / Running / Queue / Done" (`panel_view.luau`, `panel_cards.luau`). The Discard button turns into "Confirm discard" for 6 s (`panel.luau:246-266`).

**PATH discovery.** `bin.luau` + `run.luau` (pattern 20). `omp`, `git`, `gh` looked up in `bin_dirs ∪ {~/.local/bin, /opt/homebrew/bin, /usr/local/bin, /usr/bin, /bin}`; missing ⇒ result status 127 with message `omp was not found in …`. Jobs that are typed into a pane use the user's interactive shell PATH (`docs/configuration.md:27-28`).

**Docs worth reading before design:** `AGENTS.md` (rules), `docs/how-it-works.md` (§Internals, §Known limitations), `docs/troubleshooting.md` (symptom table and log lines). `skills/swarm/SKILL.md` is an agent-facing skill for setting up `.tern/swarm.json`; it is not relevant to the build.

**Limits swarm accepted (copy awareness):** needs a window; background-idle timer delays of 40-90 s; hook disable on over-budget; Linux untested; Windows/iOS/remote unsupported; only 3 s tick granularity.

### 3.2 tern-rss

**Manifest** (`plugin.toml:1-12`): one block `rss`, a host half and a window half. **Window half** (`window.luau`): an `Open <title>` command per block (via `manifest.blocks()`), a `tern.route.link` for `tern-rss://read/<pane>?url=…` and `tern-rss://carly/<id>`, Carly exports `found`/`not_found` that poll a result file every 500 ms (`window.luau:103-144`). **Host half** (`host.luau`): the block registry with error stubs.

**Periodic refresh: host-side, only while a block is open.** `store.luau`: `TICK_MS = 60000` (L64), `interval()` reads kv `config/block/rss/refresh_minutes` (default 15, min 5; L109-116), per-feed `next_at[id] = now + interval()` (L629), `pump()` starts fetches for due feeds, ≤4 in flight (L677-690), `tick` re-arms `tern.timer(TICK_MS, tick)` and **stops when no subscribers remain** (`subscribers` pruned via `poll.alive`, L690-713), and `store.attach(cx, on_change)` starts it (L720-727). Persisted: only config (kv), feed list `rss/feeds.json`, `rss/read.json` (debounced 1 s write, L235-243), per-feed caches. `next_at` is in-memory, so after a restart everything is due. It is *not* a schedule that survives; it is a pull-refresh. Toasts happen only while a block is open (README note).

**CRUD UI (direct template).** Block `blocks/rss.luau` (1205 lines; `State` at L23-45; keys at L1065-1132; events at L1134-1198; `save` at L1200):
- **Create**: `a` or paste opens an `input` field (`open_field`, L286-298; `add_nodes`, L517-535 with `placeholder`, `prompt`, `cursor` as UTF-16 count); `field_key` (L349-407) handles enter/escape/paste/backspace/delete/arrows/home/end/printable; `submit` (L312-347) calls the async `store.add` and shows spinner/error nodes (`add_busy`, `add_error`).
- **Read/list**: `ui.node("list", {key="feeds", selected="main.feeds."..id, max={lines=…}}, rows)` with `ui.node("item", {key, label=spans, detail, value=spans, tone, disabled})` (L741-814). Row `value` summarises status ("N new", "caught up", "can't refresh", "remove?").
- **Update (toggle)**: `s` stars/unstars (L983-1004).
- **Delete with confirm**: `d`/`delete`/`backspace` arms (`state.confirm = id`, L468-483), a second press removes; any other key or tab switch disarms; the hint line explains "Press d again to remove X, or esc to keep it" (L817-829), and the badge becomes "Confirm remove" with tone `error`.
- **Dock**: `hints_text` (L853-887) picks width-dependent key hints (`cx.cols < 70`, `< 56`); `dock_view` (L889-929) adds a spinner or "Updated 3m ago" plus "N feeds failing" (clickable).
- **Mouse + keyboard parity**: every action has a badge with `actions = {click = "star=<id>"}` handled in `event` (`ev.ev == "action"`; `ev.act`, `ev.value`) and rows emit `select`/`activate` events (L1134-1198).
- **Focus**: `ev.ev == "focus"` → `cx:frame({{"focus", ev.id}})` keeps focus in sync (L1196).
There is **no edit-in-place for a feed** (there is nothing to edit). Editing a job needs the swarm `new-task`-style multi-field form instead.

**Storage.** Plain JSON files in `<data>/rss/` (feeds, read state, caches) written with `tern.fs.write` after `pcall`; typed kv (`tern.kv`) only for config. Never in the package folder. Carly hand-off via `rss/carly/<id>.{request,answer,asked,result}.json` — a second example of a file-based host↔window channel (`lib/carly.luau`, `window.luau:103-144`).

**PRODUCT.md principles** (`PRODUCT.md:46-51`): *Headlines first. One key per action. Quiet until it matters. Never lose your place.* Plus: keyboard-first with pointer support (L25), inherit Tern's theme, express meaning with span tokens and tones, never colours (L38-39), the block survives window close and daemon restarts (L26), "Favorite and Carly toasts only fire while an RSS block is open" (L33), and "No accounts or sync" (L35). Translate to jobs: *Next-run time first. One key per action. Quiet until a run needs you.*

**Other**: `.impeccable/surfaces/blocks-rss-luau.md` is a design-direction contract (THESIS/STORY/FIRST VIEWPORT) — a useful format for a design brief. `lib/fmt.luau` (times, ages, counts, durations, clipping), `lib/url.luau`, `lib/feed.luau` (RSS/Atom parser, not reusable).

### 3.3 omp-pushover

**Two halves.** An omp extension (`src/`, declared via `package.json: omp.extensions = ["./src/index.ts"]` and loaded from `~/.omp/agent/config.yml` `extensions:`) and an optional Tern window plugin (`tern-plugin/`, `plugin.toml:1-7`: `window = "window.luau"`, **no host half**).

**Shared state.** `~/.config/omp-pushover/state.json` (NOT under Tern's data dir; `state.ts:48-50`), shape `{mode, away_until, snooze_until, armed[], last_error}`, Unix-second times (`state.ts:30-44`). TS: `readState` never throws and normalises (`:57-82`); `updateState(fn)` reads, mutates, writes `tmp-<pid>` then `renameSync` (atomic) (`:85-94`). Luau: `read_state` with a 64 KiB cap and validation (`window.luau:23-56`), `write_state` with `tern.json.null`/`tern.json.array` (`:58-70`). **Polling**: omp side `ctx.setInterval(refreshStatus, 15000)` (`index.ts:142`, `STATUS_REFRESH_MS` at `:12`), Tern side `tern.timer(15000)` rescheduled once at a time (`window.luau:109-118`, `REFRESH_MS` `:17`), plus an immediate refresh after each command (`:133`). `window_start` handler also re-schedules, because a reload need not emit it (`:230-235`). No file watcher, no locking; last writer wins. README: "omp sees changes made in Tern within 15 seconds".

**Status-line segment.** omp: `ctx.ui.setStatus("omp-pushover", text)` (`index.ts:42`). Tern: `tern.chrome.status(fn)` returns `{ {text, tone, command="plugin.omp-pushover.cycle"} }`; the formatter is a pure function over a cached state refreshed by the timer and `tern.chrome.refresh()` (`window.luau:103-106,209-228`). Tone `error`/`muted` by state. Clicking the segment runs a palette command, which is a nice idiom.

**Palette grouping.** `tern.command({id, title, group = "Phone push", run})`; commands get ids like `auto`, `always`, `off`, `away`, `snooze`, `arm`, `cycle` and an id→command string `plugin.<plugin-id>.<id>` (`window.luau:145-207`).

**omp extension hooks used.** `pi.on("session_start")` (starts the status interval), `"session_switch"`, `"session_shutdown"`, `"agent_start"`, `"agent_end"` (uses `event.willContinue`, `event.isTerminal`, `event.messages[].stopReason` = `aborted`|`error`), `"auto_retry_start"`, `"tool_approval_requested"`/`"tool_approval_resolved"`, `"tool_execution_start"`/`"tool_execution_end"` (`toolName == "ask"`), `pi.registerCommand("push", {description, handler(args, ctx)})`, `ctx.ui.setStatus`, `ctx.ui.notify(text, level)`, `ctx.setTimeout/setInterval/clearTimer`, `ctx.sessionManager.getSessionId()`, `ctx.cwd`, `ctx.hasUI`, `ctx.agent.kind`, `pi.getSessionName()`, `pi.logger.warn` (`index.ts:17-283`). Guards: `process.env.OMPCODE === "1"` returns early so nested omp doesn't double-report (`:19`); `process.env.TERN_PANE` identifies the pane (`:34`). Presence uses `ioreg`, `pgrep`, `stat /dev/console`, and `tern ls --json` (fallback `/Applications/Tern.app/Contents/MacOS/tern`) to find whether the pane is the focused block of a shown tab (`presence.ts:134-207`).

**Takeaway for a scheduler.** An omp-side extension buys: a `/schedule` slash command inside omp, status line, hooks on `agent_end` for notifying. It costs: a second install step (a path in `config.yml`), extensions load only at omp start (README troubleshooting), and cross-process state with no lock. The one *real* thing it could add is `agent_end`-based finish detection inside the agent, which swarm already gets from `cx.agents:list()`. `[INFERENCE]` A single Tern plugin is sufficient.

### 3.4 ternkit

A block collection, not a job runner. Reusable libs (`lib/`):
- `manifest.luau` (47): reads `[[blocks]]` id/title (same as tern-rss).
- `config.luau` (93): typed kv config `config.for_block(name, defaults)`, plugin-wide `config.get/set` (same as rss).
- `cards.luau` (74): `cards.with(node, props)`, `cards.status/loading/commands/error/empty`; `cards.error` supports `detail`, `fixes` (click-to-copy command lines) and a `retry` badge.
- `bin.luau` (28): `bin.resolve` with a shorter dir list (no `~/.local/bin`).
- `poll.luau` (100): non-overlapping poller bound to a block pane, stops when the pane disappears, `every_ms` may be a function; a pcall'd failing run still counts as done; interval floor `MIN_MS = 1000` (`poll.luau:238,256-327`).
- `source.luau` (213): load cycle for polled data with stale-answer guards (epoch-like) and loading/error cards.
- `fmt.luau` (91): `epoch(iso)`, `ago`, `compact`, `clip`, `duration`, `first_line`.
- `keychain.luau` (294), `api.luau` (377): Keychain + JSON client; not relevant.
Window half (`window.luau`): `cx.agents:start({prompt, cwd})` (without `command` or `how`) from a link route `<plugin>://investigate/<id>`, with `cwd` from kv `agent_cwd` or the clicking pane's cwd, falling back to `~` (`:150-175`) — useful precedent for a configurable working directory default. Also a "prefill" route (`ternkit://prefill/<pane>`): a block writes `{command, cwd, at}` to kv key `prefill/<pane>`, opens the link, and the route validates freshness (30 s), splits a new pane (`cx.layout:split(block,"down",{cwd})`) and types the command once `info.at_prompt` is true (up to 50×100 ms) without Enter (`:177-229`). A good reference for opening a pane and typing into it safely.

## 4. Recommendation: what to copy or adapt

**Copy near-verbatim** (generic, no task semantics): `lib/sh.luau`, `lib/text.luau`, `lib/run.luau`, `lib/bin.luau` (keep the `bin_dirs` setting; add Tern's bundled `~/Library/Application Support/Tern/omp/bin` and `~/.omp/bin`-style dirs if needed `[INFERENCE]`), `lib/roles.luau` (swap the `SKIP`/`ORDER` lists as you like), `lib/textfield.luau`, `lib/paths.luau` (`djb2`, `abs`, `dirname`, `slugify`, `unique_slug`; drop the project/board paths), `lib/store.luau` generic parts (`read_json`, `write_json`, `read_text`, `write_text`, `write_intent`, `pending_intents`, `remove_intent`, the damage/format pattern from `save_projects`/`load_task`), and the `window.luau` staged loader skeleton.

**Copy with light adaptation**: `lib/orchestrator.luau` (keep lease, epoch, `schedule`, `poke`, intent drain, watchdog `recover`; replace the project/board reconcile with a `due jobs → start run → track run` step; use a 10-30 s tick), `lib/state.luau` (drop board fields), `lib/intents.luau` (kinds: `create`, `update`, `delete`, `toggle`, `run_now`, `config`), `lib/steps.luau` `track_agent` + `placement` (reduce to running/waiting/finished/failed and keep the foreign-pane detection), `lib/prepare.luau` `start_agent` (drop worktree/shell/setup), `lib/commands.luau` (palette group + status segment + `focused_cwd` remote refusal), `lib/carly.luau` (`list_jobs`, `add_job`, `set_job_enabled`, `run_job_now`; keep `fit` and the allowlist), `blocks/new-task.luau` (title + prompt `editor` + role `list` + add schedule/cwd/placement fields), `lib/schema.luau` + `lib/config.luau` for a *user-only* settings file.

**Adapt the UI patterns from tern-rss rather than files**: the list/item/dock/hints/two-press-delete structure of `rss.luau` (`feeds_view`, `remove_feed`, `hints_text`, `dock_view`, `field_key`) is the best CRUD reference for the jobs list. The swarm panel (`panel.luau`, `panel_cards.luau`) is the reference if the list is a canvas shared across windows instead of a host block.

**Do not copy**: worktree/git/ship/checks/cleanup/board code (`git`, `ship`, `cleanup`, `prepare` git parts, `checking`, `cardsync`, `reconcile`, `boardread`, `jobs`), rss's host-side refresh loop (needs an open block, has no `cx`), the whole ternkit API/keychain stack, the omp-pushover extension (unless an omp-side feature is justified).

**Design implications that fall out of the evidence** (for the later design phase, not decisions):
1. The scheduler tick must live in the **window half**, leader-elected via `tern.kv`; **host half only for forms** (job editor, settings), talking to the leader through intents + a `…://wake` route.
2. **Fires only while at least one Tern window is open**, and can be late by 40-90 s in the background; needs a documented missed-run policy and a "last run / next run" display.
3. Launch with `cx.agents:start({prompt, cwd, how, command = "omp --model '@<role>' …"})`, restore focus afterwards, and track the pane through `cx.agents:list()`. `how` = `tab | split | replace_if_alone` is a natural per-job "where" setting. `[INFERENCE]` Verify on 0.7.2 that `command` is still honoured, since swarm was built on 0.5.2.
4. Because runs are unattended, decide `--approval-mode` explicitly (swarm: default yolo, user-layer only) and add `--max-time` (swarm passes it per role).
5. The status segment + palette group ("Schedule: …") + optional canvas panel are all proven patterns in swarm; the CRUD form is the swarm `new-task` shape; the list-with-confirm-delete is the rss shape.
