# Consistency review: architecture / ux / engine / launch

Reviewer: ReviewConsistency. Scope: cross-document conflicts only. Docs: `AR` architecture.md, `UX` ux.md, `EN` engine.md (+ engine-src), `LA` launch.md. Evidence is quoted from the docs by section; runtime facts from `research/tern-probe2.md` (PR2).

Authority used for recommendations: AR decides structure; PR2 beats docs; EN owns data/policy/state; LA owns argv/process mechanics; UX owns words and widgets.

Severity key: **B** blocker (implementer cannot build without choosing; or user-visible promise impossible), **M** major (two docs would produce incompatible code/data), **m** minor (naming/copy/threshold).

## 3. Remaining blockers/majors in detail

### C25 (B). Pinned model has nowhere to live
- UX §4.4: "Other model…" → "Model id or selector (e.g. anthropic/claude-sonnet-5-5:low)"; chips show `claude-sonnet-5-5`, hint "Pinned: won't follow role changes."
- EN §1.1 `role` validation `^[%w_%-]+$`; becomes `--model '@role'`.
- LA §6 "A role named with characters outside `[%w_-]` is rejected at creation."
- Resolution: either **drop** "Other model…" from UX §4.4/§7.5 (recommended for v1: roles are omp's abstraction and cover the need) or add `model` (string, ≤200, `^[%w%._:/%-]+$`, mutually exclusive with `role`) to EN and pass `--model <selector>` in LA. Also `Couldn't find a model matching “x”` copy requires an omp model lookup (`omp models --json`) not in LA.

### C26 (M). Default cwd `$HOME` conflicts with launcher
- EN §1.1 default: "focused local pane's cwd at creation, else `$HOME`"; UX §4.5 fallback `~`, only a warning "omp works in a temporary folder".
- LA §5: `cwd == HOME and not allow_home → blocked cwd_home`.
- Resolution: add `allow_home` (boolean, default false) to EN §1.1 **or** refuse HOME in the form (UX §4.5 error instead of warning) so a default of `$HOME` is never a valid save. Recommend refusing `~` in the form: "Pick a project folder; omp won't work in your home folder." and drop `allow_home`/`--allow-home` from LA (YAGNI). If the user has no focused cwd, leave Folder empty (required).

### C27 (M). What happens with zero windows
- UX §5.1: "needs-you and failures still send the OS notification if enabled" with no window.
- EN §7.3 final paragraph: without a window needs-you cannot be detected; run ends at its deadline.
- LA §8.4: run remains `running` `observed=false`, "Running (not observed: no Tern window open)"; on first window → `finished` with `late`.
- EN T2: host may finish via `pane_exited` + session-file tail (`ok_unobserved`) `[INFERENCE]`.
- Resolution (one availability contract in AR §Availability): without a window the host can detect only **exit, liveness, deadline**; no needs-you, finish only via T2 `[INFERENCE O4]`. Copy: UX §5.1 last row → "Failures that end in an exit still send the OS notification; waiting-for-you is only detected while a Tern window is open." LA §8.4/§11 #20 reword to the EN tiers. The "late" finish from the first window tick is EN `unobserved` or `observed_late`: choose one flag (§2 table).

### C-engine-ux-session (m). UX 4.9 spec cross-check list
- "Run after it finishes (at most one waits)" ✓ EN `queue`.
- Settings "keep run history: last 50 runs per job for 90 days" ✓ EN.
- UX §3.2 "Recent runs: last 10 runs of any job" vs UX §2.2 #6 "last 30" vs detail "last 20" vs EN snapshot "recent runs" (cap unspecified): fix numbers in EN snapshot spec: 30 global, 20 per-job in detail.

### Cost and summary
- UX "$0.42"/"This month: 18 runs · $7.31"; LA authoritative cost from session JSONL (V22 unverified); EN `cost_line` string only, no numeric field. Add `cost_usd?` (EN), define "—" when nil, and make "This month" a query over ledgers (retention 50 runs/90 d bounds it).

### Hot snapshot sizes
- EN `snapshot.json` cap 128 KiB read by every window; LA adds `roles[cwd]` there. EN §2.1 "windows never read files > a few KB" contradicts a 128 KiB snapshot read every poll. Fix: windows read snapshot only when `rev` changes; cap 32 KiB; keep roles in a separate `roles.json` read only by the form.

The overlay is a file the plugin writes under the run dir: record in EN storage layout and mark as depends-on-V14; if V14 fails, UX copy "never asks" must soften to "doesn't ask for approval".
